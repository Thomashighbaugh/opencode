# Find Commands

Find and generate the right OpenCode slash commands for a project by searching registries, scanning local packs, and presenting candidates for installation.

## When to Use

- During `/hub-setup setup` or `/hub-setup refresh` to scaffold project commands
- When the user asks "find a command for X" or "is there a command for X"
- After `@stack-detector` has produced a stack fingerprint, before `project-config-composer` runs
- To extend a project with reusable workflows invoked as `/command-name`

## What a command is

An OpenCode command is a markdown file with YAML frontmatter at `.opencode/commands/{name}.md`, invoked as `/command-name`. It carries a reusable workflow, optional `$ARGUMENTS` placeholders, and an argument hint. The Claude Code `.claude/commands/*.md` format is compatible, so the wider slash-command ecosystem is a valid source.

## Multi-Source Search Strategy

| Source | Search Method | Signal |
|--------|--------------|--------|
| **Local templates** | `ls ~/.config/opencode/templates/commands/*/` (if present) | Known-good templates |
| **GitHub topics** | `gh search repos --topic opencode-commands --topic claude-commands` | Stars, description |
| **GitHub code** | `gh search code --filename '*.md' path:.claude/commands <term>` | Real command implementations |
| **skills.sh** | `npx skills search <term>` | Install count |

## Output

A list of command candidates with installation status:

```json
{
  "commands": {
    "from_templates": [],
    "from_registries": [
      { "name": "release-prep", "source": "github:user/commands", "status": "found" },
      { "name": "db-migrate", "source": "skills.sh:owner/pack", "status": "found" }
    ],
    "selected": [
      "release-prep", "db-migrate"
    ]
  }
}
```

## Integration with /init-project

After `stack-recommender` produces recommendations, `find-commands` is called to:
1. Check which recommended workflows have local templates
2. Search registries for workflows without local templates
3. Present findings for user selection
4. Pass the selected list to `project-config-composer` (or `opencode-command-creator`) for generation

## How to Choose the Right Command

1. **Fit** — Does the command's workflow match a task this project repeats?
2. **Argument shape** — Prefer commands whose `$ARGUMENTS` match how you would invoke them
3. **Portability** — Claude Code `.claude/commands` files port directly; verify they do not assume Claude-only tools
4. **Safety** — Review what bash/edit access the workflow needs before adopting it

## Installation

Commands are generated by `opencode-command-creator` into `.opencode/commands/`. Registry commands are ported (copied and adapted) rather than auto-installed — present them for review first.

## Security & Privacy

- Issues read-only HTTP GETs to public APIs
- Local template scanning reads files only
- Never executes command bodies during search
