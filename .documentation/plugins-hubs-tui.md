# TUI Plugin — `plugins/hubs-tui/`

A native terminal UI for the hub command system. 899 LOC of `tsx` compiled to a Bun bundle.

Registered as `"plugin": ["file://./plugins/hubs-tui/dist/tui.js"]`.

---

## What it provides

- **Hub command palettes** — every one of the 14 hubs as a `DialogSelect`, grouped and
  searchable.
- **The `/focus` command** — a native slash command for session focus state.
- **Prompt stashing** — stash the current input, retrieve it later.

---

## The generated bundle

The TUI is served from a **generated** artifact, not from the source manifests.

```
tools/hub-*.ts              ← canonical: 14 thin hub manifests
        │
        │  bun run generate-menus
        ▼
src/generated-hubs.ts       ← COMMITTED (15 hubs, 188 subcommands)
        │
        │  bun build src/tui.tsx --outdir dist --target bun --minify
        ▼
dist/tui.js                 ← gitignored, rebuilt locally
```

**This is the single most-skipped step in the repository.** Adding a subcommand to
`tools/hubs/<hub>/<subcommand>.ts` and nothing else produces a subcommand that is completely
invisible in the dialog — the file compiles, the registry updates, and the user simply never sees
it. `rules/hub-menu-rebuild.md` exists because of that, and
`tests/global/feature-package.test.ts` asserts the generated bundle contains every registered
subcommand.

```bash
cd plugins/hubs-tui
bun run generate-menus
bun build src/tui.tsx --outdir dist --target bun --minify
```

## Descriptions are a UI constraint, not a style preference

`rules/hub-description-directive.md` sets a 80-character limit, and the reason is measurable: the
dialog truncates past it, so the text meant to help a user choose was the part they could not
read.

The state before this work:

| Measure            | Count |
| ------------------ | ----- |
| Over 80 characters | 95 / 183 |
| Over 100           | 70 / 183 |
| Over 120           | 48 / 183 |
| Longest            | 243   |

All 95 were rewritten. Maximum length is now exactly 80, and no two subcommands in the same hub
share a description — two identical descriptions in a flat list is an unactionable choice.

A second test rejects descriptions that assume the **hub name is visible**. The dialog shows the
subcommand name in a flat list; `Configure X` is ambiguous when three hubs have a configure.

Truncation was rejected as a shortcut: a mechanically cut description is worse text than a long
one, and the cost of 95 rewrites is lower than the cost of 95 bad strings.

## Interdependencies

| This plugin uses | From |
| ---------------- | ---- |
| `tools/hub-*.ts` manifests | [Hub Command System](hub-command-system.md) |
| `tools/hubs/spec-registry.json` | generated by `tools/build-spec-registry.ts` |
| `DialogSelect` from the Hubs TUI framework | `hubs-tui-hubs` |

Any change to a hub spec requires regenerating both `tools/hubs/spec-registry.json` **and** this
plugin's bundle. OpenCode must be reloaded afterwards, since `dist/tui.js` loads at startup.
