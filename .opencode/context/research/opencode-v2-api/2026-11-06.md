## Nix packaging fact

`numtide/llm-agents.nix` exposes two distinct packages from the same lock entry:

- `opencode` → 1.19.5, binary `opencode`, installs the GitHub release binary.
- `opencode2` → 2.2.0, binary `opencode2`, installs `@opencode/cli-<platform>` from npm.

`packages/opencode2/package.nix` installs upstream's `opencode` binary as `opencode2` explicitly
"so it can coexist with the v1 `opencode` package". Coexistence is by name only; see the database
section for the shared-state hazard.

## V2 plugin API

`Plugin.define({ id, setup(ctx) })` from `@opencode/plugin`. Context domains replace the V1
`client` object. Registrations are transforms; hooks are `ctx.<domain>.hook()`; cleanup returned
from `setup`; durable plugin state in `ctx.storage`.

| Capability | Signature | Source |
| --- | --- | --- |
| Tool registration | `ctx.tool.transform(editor => editor.add({ name, description, input: JSONSchema, output?, options?, execute }))` | `packages/plugin/src/promise/tool.ts` |
| `codemode: false` keeps a tool on the native tool list | `options: { codemode: false }` | `packages/core/src/tool/plugin/todo.ts` |
| Skill registration | `ctx.skill.transform(editor => editor.add(skill))` where `Skill.Info = { id, name, description?, autoinvoke?, path, content }` | `packages/plugin/src/promise/skill.ts:6-16`, `packages/schema/src/skill.ts` |
| Command registration | `ctx.command.transform(editor => editor.add({ name, description?, execute(input) }))`, `input: { sessionID, prompt, delivery }` | `packages/plugin/src/promise/command.ts:6-24` |
| MCP registration | `ctx.mcp.transform` with `MCPEditor` | `packages/plugin/src/promise/mcp.ts` |
| Events | `ctx.event.subscribe({ signal })` | V2 docs, migrate-v1 |
| Storage | `ctx.storage.get/set` | same |

## V2 built-in tool names

`packages/core/src/tool/plugin/`: `shell`, `read`, `write`, `edit`, `glob`, `grep`, `skill`,
`subagent`, `webfetch`, `websearch`, `question`, `todowrite` (v2.2.6 only), `mcp-resource`.

V1→V2 renames that matter: `bash`→`shell`, `task`→`subagent`, `loadSkill`→`skill`. There is no
built-in `listAgents`, `agentContext`, `modeState`, `taskTodos`, or `artifacts`.

## TUI plugin API

Import `@opencode/plugin/tui`, export the package's `./tui`. Context (`packages/plugin/src/tui/context.ts`):

| Surface | Shape | Line |
| --- | --- | --- |
| `ui.dialog.select` | `select<Value>({ title, placeholder?, options: [{ title, value, description?, footer?, category?, disabled? }], current?, search?, actions? })` → `Promise<Value \| undefined>` | 355-404 |
| `keymap.layer` | `{ mode, priority, commands: [{ id, title, group, bind, slash: { name, aliases?, arguments? }, palette, enabled, suggested, run }] }` | 405-446 |
| `ui.router.current()` | returns `Route`; session route carries `{ type: "session", sessionID }` | 142-152, 499 |
| `client` | `OpenCodeClient` — full V2 HTTP client, e.g. `client.session.prompt({ sessionID, text })` | 549 |
| `data.location.mcp` | `{ server, resource }` collections **only** — no MCP tool-call API | 131-133 |
| `ui.panel`, `ui.slot`, `ui.toast`, `ui.tabs`, `ui.model` | panel/slot/toast/tab/model surfaces | 168-540 |
| `storage.store`, `storage.memory` | durable and in-memory plugin state | V2 docs, TUI |

No composer-text API exists in the TUI context: a picker submits by calling the client, not by
filling the prompt box.

MCP elicitation has no TUI renderer: the only `elicit` implementation is
`packages/cli/src/acp/elicitation.ts` (ACP). Do not plan on MCP forms as a selection UI.

## Commands

`.opencode/commands/*.md` and the JSON `commands` map; `$ARGUMENTS`, `$1..$n`; shell blocks
`` !`cmd` ``. No arguments UI. Plugin-registered commands are programmatic and receive the session
invocation, so they can submit prompts directly but cannot render a picker.

## Storage, database, and coexistence

- App directory name is the literal `"opencode"` (`packages/util/src/global.ts:12-19`), so V1 and V2
  share `~/.local/share/opencode`, `~/.config/opencode`, `~/.local/state/opencode`.
- V1.19.5 DB filename (`packages/core/src/database/database.ts:43-54`): `opencode.db` when channel ∈
  `[latest, beta, prod]` or `OPENCODE_DISABLE_CHANNEL_DB`; otherwise `opencode-<channel>.db`.
- V2.2.x DB filename (`packages/cli/src/database-path.ts`): `opencode.db` when channel ∈
  `[latest, dev, beta, next, prod]` or the same env flag; otherwise `opencode-<channel>.db`.
- Both call `DatabaseMigration.apply(db)` at open. Pointing V2 at the V1 file rewrites its schema.
  There is no version guard.
- Deterministic isolation for V2 testing: `OPENCODE_DB=opencode-v2.db`.

## Config deltas relevant to this tree

- `permission` map → ordered `permissions` array; actions renamed (`bash`→`shell`, `task`→`subagent`,
  `write`/`patch`→`edit`).
- `plugin` → `plugins`, object entries, local paths must be directories.
- `provider` → `providers`, `npm` → `package` with `aisdk:` prefix, `options` split into
  `settings`/`headers`/`body`.
- Model fields `release_date`, `attachment`, `reasoning`, `temperature` are ignored with warnings;
  use `capabilities.{tools,input,output}` and `variants` arrays.
- `tui.json(c)` → single global `cli.json`.
- Todos off by default; LSP config accepted but inert (no servers, tools, or diagnostics).
