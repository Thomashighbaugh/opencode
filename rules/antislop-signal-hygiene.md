# Anti-slop Signal Hygiene — slopscore-derived contrapositive gate

**Method (contrapositive of slopscore detection).**

slopscore determines slop by finding signals in a repository: commit history (committer name, committer email, commit-message phrases such as "generated with/by/using", "co-authored by") and source tree (AI tool directories and files such as `.claude`, `.cursor`, `.codex`, `CLAUDE.md`, `CODEX.md`). Its rule is: signal present → slop likely.

The contrapositive is: not-slop requires no signal present. This rule inverts slopscore's *detection* into a *pre-flight prevention*: before any artifact you produce is delivered — a commit, a file, a message, output text — scan it for slop signals. If any signal matches, the artifact is treated as slop and delivery is blocked until the signal is removed.

**Signal categories** (adopted from slopscore's detection taxonomy):

| Category | What is scanned | Example signals |
|----------|-----------------|-----------------|
| Authorship | committer name / email | names: claude, cursor, copilot, codex, cline, aider, amp; emails: `@anthropic.com`, `@cursor.so`, `copilot@github.com`, `noreply@openai.com`, `aider@aider.chat` |
| Message | commit-message or produced text phrases | "generated with", "generated by", "co-authored by", "co-developed by", "made-with", tool self-identification |
| Source tree | directories and files introduced into the tree | `.claude`, `.cursor`, `.codex`, `.cline`, `.windsurf`, `.aider`, `.continue`, `.devin`, `CLAUDE.md`, `CODEX.md`, `.cursorrules`, `.clinerules`, `.windsurfrules` |
| Detector | impeccable design findings | `skills/impeccable/scripts/impeccable detect` findings (62 slop rules) reported via command hooks on UI file edits |

**Delivery gate.** Every deliverable must pass a signal scan before it is finalized:
- commits: message, author name, author email
- files: path and content for AI-dir/file markers and generation phrases
- messages/output: text for generation phrases and tool self-identification
- UI files: impeccable detector findings — any P0/P1 finding blocks delivery

A match is a FAIL. Remove the signal or record an explicit, written ignore (analogous to slopscore's `ignore_signals`) before delivery.

This rule is auto-loaded for every session using this configuration, so it applies to all OpenCode use of this repo regardless of who is driving.

Source: https://codeberg.org/polyphony/slopscore
